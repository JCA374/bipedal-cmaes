Evolution strategies and CMA-ES

How do you climb a landscape you can't see, when the only thing you can do is stand somewhere and measure the height? You throw a cloud of guesses, keep the best, and learn the shape of the cloud as you go.

After this lesson you can
  • describe one generation of an evolution strategy: sample, evaluate, rank, update;
  • explain the three things CMA-ES adapts (mean, step size, covariance) and why each one matters;
  • read the ten-line training loop that evolves the walker.

1Guess, test, keep the best

Lesson 2 ended with a problem: we have a fitness function f(θ) over 932 numbers. We can measure it (run the walker, read the reward), but we have no gradient telling us which way is uphill.

An evolution strategy (ES) works like this:

  1. Keep a current best guess, the mean m.
  2. Sample λ ("lambda") candidates around it: m + σ · (random noise). σ ("sigma") is the step size.
  3. Evaluate every candidate: let each one walk and record its reward.
  4. Rank them and move m to a weighted average of the best half.
  5. Repeat. One round is one generation.

Only the ranking matters, not the exact scores. That makes ES robust: a reward of 280 vs 290 and one of −100 vs 290 lead to the same update, so a few wild outliers can't throw it off.

3What CMA-ES adapts

CMA-ES (Covariance Matrix Adaptation Evolution Strategy, Hansen & Ostermeier, 1996–2001) is an ES that learns three things as it goes:

The mean m: where to search

A weighted average of the best μ = λ/2 candidates, with the best one counting most.

The step size σ: how far to search

CMA-ES keeps an evolution path, a running sum of its recent moves. If recent moves point the same way, it is walking up a long slope, and σ grows. If they cancel each other out (back and forth), it's circling around something, and σ shrinks. This is called cumulative step-size adaptation.

The covariance matrix C: in what shape to search

This is the "CMA" part. C describes the shape of the cloud: an ellipse in 2-D, an ellipsoid in 932-D. After each generation, C is stretched toward the directions the successful candidates came from. Over time the cloud lines up with the landscape, so it samples mostly along the valley and wastes few samples climbing its walls.

For the walker this means "which weights should move together"Here C is a 932 × 932 table: 868,624 numbers, one for every pair of weights. If increasing a hip weight only helps when a knee weight increases too, C learns that correlation and starts proposing both changes together. A plain ES would have to stumble on that combination by luck every time.

All of this needs no gradient and no knowledge of the physics: just "which candidates ranked best". Because the cloud's size and shape adapt by themselves, CMA-ES has almost no knobs to tune. The main ones are λ and the starting σ.

4The training loop

This is the actual core of train.py (using the cma Python package):

es = cma.CMAEvolutionStrategy(np.zeros(932), 0.5, {"popsize": 48})
while not done:
    thetas  = es.ask()                         # 48 candidate walkers
    terrain = new_random_terrains(k=5)          # the same 5 tracks for all 48
    fitness = [mean(walk(θ, t) for t in terrain) for θ in thetas]   # 240 episodes, on 4 CPU cores
    es.tell(thetas, [-f for f in fitness])     # cma minimises, so negate
    every 10 generations: re-test es.mean and the best 3 on 20 held-out tracks → champion

The starting point is all zeros, a network that outputs nothing. σ = 0.5 means the first candidates are fairly random. Each generation costs up to 48 × 5 × 1600 = 384,000 simulation steps, but most early walkers fall quickly, so early generations take 1–3 seconds on this laptop.

5Why not gradients?

Deep RL methods like PPO and TD3 (which I tried in earlier projects) estimate a gradient from individual steps: "this action at this moment led to more reward than expected". That's powerful and uses fewer simulation steps, but it needs value estimates, replay buffers and many hyperparameters, and it can be unstable.

An ES only looks at the total reward of whole episodes. It's simpler, every episode runs in parallel, and it doesn't care whether the reward is smooth, delayed or sparse. The price is samples: it usually needs many more episodes. This project tests how far that simple approach gets: NEAT reached about 175, PPO 272, TD3 308–319. Can CMA-ES reach 300?

Check yourself

1. Two candidates score 250 and 260 in one generation; in another, they score −100 and 260. How does CMA-ES treat these differently?

CMA-ES uses ranks. The better candidate is better by the same rank in both cases, so the update is the same.

2. CMA-ES's last few steps all point roughly the same way. What happens to σ?

A long evolution path (moves that add up) means it hasn't reached the optimum yet, so σ increases.

3. What does the covariance matrix capture for the walker?

C learns correlated directions in weight space and shapes the sampling cloud along them.
